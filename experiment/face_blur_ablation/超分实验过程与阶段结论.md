# 监控糊脸超分实验过程与阶段结论

> 这是一份面向项目成员和非算法背景读者的过程说明。它不替代现有技术论文，重点回答三个问题：我们为什么做超分实验、实验过程中遇到了什么问题、目前能得出什么阶段结论。

## 先看结论

我们最初希望用图像超分修复监控视频中的模糊人脸，让系统更容易认出人。经过多轮数据筛选、协议修正和三种超分算法对比后，当前结果并不支持把超分默认接入自动身份识别流程。

在最关键的 40 条“有修复价值”的 Query 上：

| 处理方式 | 第一名身份正确 | 相比原图 | 救回 | 损害 |
| --- | ---: | ---: | ---: | ---: |
| 保留原图 | 26/40（65.0%） | -- | -- | -- |
| GFPGAN | 8/40（20.0%） | 下降 45.0 个百分点 | 0 | 18 |
| CodeFormer | 11/40（27.5%） | 下降 37.5 个百分点 | 0 | 15 |
| Real-ESRGAN | 18/40（45.0%） | 下降 20.0 个百分点 | 1 | 9 |
| 只缩放到 512 再缩回 | 26/40（65.0%） | 不变 | -- | -- |
| 只放大 2 倍再缩回 | 26/40（65.0%） | 不变 | -- | -- |

这里的“救回”是指原图认错、超分后认对；“损害”是指原图认对、超分后反而认错。GFPGAN 和 CodeFormer 没有救回任何样本，Real-ESRGAN 只救回 1 条，但损害了 9 条。两个纯缩放控制都没有改变结果，说明问题不在于图片尺寸往返，而在于超分生成的细节改变了身份特征。

因此，当前产品策略是：

- 身份识别默认使用原始对齐人脸，不自动使用超分结果。
- 超分只保留为人工查看或显式实验能力，不能自动写入身份库。
- FIQA 只作为诊断信息，不再决定分桶、建库、超分路由或身份匹配。
- 下一阶段优先改进原始采集、人脸感知选帧和多帧证据，而不是继续无条件增强图片。

这个结论只适用于本阶段使用的数据、模型和参数，不能扩大为“所有超分算法在所有场景都无效”。

### 整个过程一览

| 阶段 | 当时看到的问题 | 做出的调整 |
| --- | --- | --- |
| 发现问题 | 监控中的脸太小、模糊或不可见 | 先测试 GFPGAN 能否补回身份信息 |
| Market-1501 | 几乎只有极小脸和无脸 | 确认人形兜底有价值，但换数据验证超分 |
| ChokePoint | 绝大多数样本挤在 marginal，小闭集过于简单 | 转向身份更多、轨迹更完整的 MEVID |
| 首轮 MEVID | 27 个身份只有 1 个能建立人脸模板 | 单独审计 Gallery 建库覆盖 |
| 首轮超分 | 498 张脸中 GFPGAN 只触发 3 张 | 重新检查质量规则和超分门控 |
| 放宽门控 | 路由又覆盖了几乎所有脸，多帧聚合还会相互污染 | 拆分质量与处理资格，每条 Query 独立选 face-best |
| 尝试 FIQA | 希望找到更多真正“可修复”的中等质量脸 | 用独立数据检验 FIQA 与识别正确性的关系 |

| 多后端正式实验 | 三种超分都低于原图 | 产品默认保留原图，超分默认关闭 |

## 一、问题从哪里开始

监控视频里经常出现以下情况：

- 人脸很小，放大后只有少量像素；
- 运动造成模糊；
- 人物侧脸、低头或被遮挡；
- 人体画面清楚，但脸并不清楚；
- 有些轨迹根本检测不到脸。

这些情况会带来三种完全不同的问题：

1. **不能识别**：画面没有足够信息，系统应该拒绝判断。
2. **不能建库**：画面勉强能看，但不适合作为以后匹配的身份模板。
3. **错误识别**：系统给出了一个看似确定、实际上错误的身份。

我们一开始的直觉是：如果把模糊人脸“修清楚”，识别模型也许能提取到更多身份信息。GFPGAN 正是为人脸修复设计的，因此成为最早测试的方案。后续又加入 CodeFormer 和 Real-ESRGAN，判断问题是 GFPGAN 特有，还是生成式超分的普遍风险。

## 二、第一步不是跑模型，而是找到合适的数据

实验最先遇到的困难并不是算法，而是数据。要判断超分有没有用，数据必须同时具备：

- 同一个人的清晰参考照片；
- 独立的模糊 Query；
- 可靠的身份标签；
- 足够多“不是完全不可用、又确实有修复空间”的样本；
- 多个身份，避免小型闭集过于简单。

### 1. Market-1501：能验证人形兜底，但不能公平验证人脸超分

第一轮使用 Market-1501，抽取了 25 个身份、148 张测试图。结果中，人脸识别约为 29.7%，人形 ReID 兜底约为 92.6%，全栈约为 91.9%。

这个结果说明：当脸太小或根本没有脸时，人形特征确实能帮助系统继续跟踪身份。但它不能直接证明超分有效或无效，原因是：

- Market-1501 中的人脸几乎都属于极小脸或无脸；
- 没有足够的清晰脸和中等模糊脸；
- 人形模型可能利用衣服、背景和同机位信息，不能等同于跨场景身份识别。

也就是说，这批数据适合验证“没脸时能不能用人形兜底”，不适合回答“模糊脸修复后会不会认得更准”。

### 2. ChokePoint：有更多人脸，但分布过于集中

为了补充清晰和中等质量人脸，我们尝试了 ChokePoint。125 张测试图中：

- clear：5 张；
- marginal：113 张；
- poor：7 张；
- none：0 张。

这次虽然出现了大量中等质量人脸，但 90% 以上样本都挤在 marginal 一档，clear 和 poor 又太少。加上小型闭集中的候选身份很少，结果很容易接近 100%，不同方案之间拉不开差距。

这次尝试告诉我们：**样本“看起来更像人脸”不等于适合做算法对比**。如果质量分布和身份难度不合理，再漂亮的数字也没有判断价值。

### 3. 转向 MEVID：用完整监控轨迹重做实验

最后选择 MEVID，是因为它同时提供：

- 多摄像头监控轨迹；
- 可追溯的身份标签；
- actor check-in 参考照片；
- 不同距离、姿态、遮挡和清晰度；
- 官方 Query 列表和更大的身份空间。

MEVID 更接近我们真正关心的监控场景，但它也暴露出更多真实问题：参考照片不一定都适合建库、同一轨迹有多帧、人脸质量与人体质量并不一致、简单阈值不能可靠判断哪些脸值得超分。

## 三、第一轮 MEVID 实验为什么仍然不能回答问题

### 1. 建库规则太严格，几乎没人能建人脸库

早期协议只允许非常清晰的人脸进入 Gallery。结果 27 个测试身份中只有 1 个能建立人脸模板。此时即使识别结果很差，也不能说明模型本身不行，因为系统根本没有足够的参考人脸可以匹配。

这一轮的主要发现不是“哪个模型更好”，而是：**人脸库覆盖不足已经先于识别模型成为瓶颈**。

### 2. GFPGAN 门控太窄，498 张脸只触发了 3 张

在另一轮人脸模型实验中，共有 180 条有效轨迹、498 张可处理人脸，但旧超分门控只让 3 张脸进入 GFPGAN。超分前后 Rank-1 完全没有变化。

这个结果不能解释成“GFPGAN 没用”。更准确的说法是：**门控几乎没有给 GFPGAN 有意义的测试机会**。

这也是后来考虑引入 FIQA 的直接原因之一：当时仅用清晰度、尺寸和检测分判断质量，视觉上很差的人脸可能没有被选入“可修复”组。

### 3. 放宽门控后又走向另一个极端

我们随后扩大了门控范围。一次审计中，基础方案处理了 1305 张可对齐脸，路由方案处理了 1238 张，差异只有 5.1%。这说明路由几乎覆盖了所有样本，B 组和 C 组实际上在做相近的事情。

门控从“几乎不触发”变成“几乎全触发”，仍然不能回答问题。更重要的是，当时还把同一轨迹的多张人脸 embedding 聚合在一起。只要其中几张被超分改坏，就可能污染整条轨迹的结果。

这轮结果被保留为诊断证据，但没有进入正式结论。

## 四、实验过程中发现的几个“小问题”

这些问题看起来像实现细节，实际上决定了实验是否可信。

### 1. “画面质量差”和“值得超分”不是一回事

最初只有一套质量分桶：

- clear：清晰；
- marginal：勉强可用；
- poor：质量差；
- none：没有脸。

但 poor 可能由完全不同的原因造成：

- 单纯模糊，可能还有修复价值；
- 人脸太小，原图根本没有足够身份信息；
- 极端侧脸或遮挡，超分无法补回真实结构；
- 检测框不可靠，修复对象本身就可能不对。

所以后来把“看到的质量”和“产品该怎么处理”拆成两条轴：

| 维度 | 类别 | 回答的问题 |
| --- | --- | --- |
| 画面严重程度 | clear / marginal / poor / none | 这张脸看起来有多差？ |
| 产品处理资格 | direct / recoverable / unusable / none | 应该直接识别、尝试修复、拒绝，还是根本没有脸？ |

这样，一张 poor 人脸既可能是 recoverable，也可能是 unusable。正式实验只把 recoverable 作为超分主检验组，避免把“本来就不可能恢复”的样本混进来稀释结论。

### 2. 人体最佳帧不等于人脸最佳帧

早期产品会先选“人体最清楚”的一帧，再从中取脸。但人物全身清楚，并不代表脸最大、最正或最清楚。

正式实验改为：

1. 每条 Query 先确定性抽取有限帧；
2. 每帧做人脸检测与对齐；
3. 使用尺寸、姿态、检测分和清晰度做与身份无关的选帧；
4. 每条 Query 只保留一张 face-best 作为输入。

身份识别结果不能参与选帧，否则相当于先看答案再挑图。

### 3. Gallery 不能默认使用所有 check-in 照片

MEVID 的 actor check-in 文件夹提供了参考照片，但这些照片并不天然都是清晰、正脸、可建库的标准证件照。正式准备阶段审计了 2,898 张照片、172 个前缀，经过产品质量门控后，343 张脸形成 145 个身份模板。

这一过程同时检查：

- 身份前缀是否重复或缺失；
- 人脸是否可检测、可对齐；
- 是否达到 direct 和 clear 要求；
- 文件摘要是否稳定，避免不同方案误用不同 Gallery。

### 4. 纯缩放也必须单独做控制

三种超分都会改变输入尺寸。如果结果下降，必须确认到底是算法生成内容造成，还是“放大再缩回”本身造成。

因此正式实验增加了两个控制组：

- Resize-512；
- Resize-x2。

两组都保持 26/40（65.0%），与原图完全相同。这排除了尺寸往返这一解释。

### 5. Rank-5 不能被误解为产品识别成功

离线评估中的 Rank-5 只表示“真实身份出现在前五名候选中”。产品不能一次向用户返回五个身份，所以实际自动匹配仍然使用：

- 最相似的第一名候选；
- 第一名分数达到当前模型阈值；
- 与第二名之间没有明显歧义。

当前 ArcFace 的接受条件是 `score >= 0.45`。Rank-5 适合帮助分析候选歧义，不代表系统已经识别成功。

## 五、为什么尝试 FIQA，后来又为什么放弃

### 1. 引入 FIQA 的动机

在早期数据中，我们遇到了两个相反的问题：

- Market-1501 几乎只有极小脸和无脸，中间质量样本不足；
- ChokePoint 又几乎全部集中在 marginal。

同时，简单清晰度指标会漏掉一些“肉眼很差、数值却不低”的人脸。因此我们考虑引入 CR-FIQA，希望它能更接近“这张脸是否适合做身份识别”，并帮助扩大或优化 recoverable 分桶。

### 2. 诊断结果没有支持这个设想

在正式诊断中，632 条候选轨迹里有 118 条得到有效人脸，最终形成 39 条参考记录和 49 条独立测试记录。

结果如下：

- ArcFace 第一名身份正确：9/49（18.4%）；
- 第一名正确且达到 0.45 产品阈值：0/49；
- CR-FIQA 与“是否认对”的相关系数：0.026，几乎没有关系；
- 去掉最低 10% FIQA 后，准确率约 20.0%；
- 去掉最低 20% 后，准确率约 17.5%；
- 去掉最低 50% 后，准确率约 16.0%。

也就是说，FIQA 高的脸并没有稳定地更容易被当前 ArcFace 认对。它可以描述某种图像质量，但不能直接当作当前系统的身份可识别性。

### 3. 超分进一步说明“看起来更好”不等于“身份更准”

三种超分的诊断结果更能说明这个问题：

| 后端 | 单脸时间 | 原图与超分特征相似度 | FIQA 变化 | 身份结果 |
| --- | ---: | ---: | ---: | --- |
| GFPGAN | 0.236 秒 | 0.402 | +0.468 | 下降最大 |
| CodeFormer | 0.324 秒 | 0.584 | +0.154 | 明显下降 |
| Real-ESRGAN | 0.075 秒 | 0.783 | -0.142 | 三者最好，但仍低于原图 |

GFPGAN 让 FIQA 提升最多，却让身份结果下降最多；Real-ESRGAN 的 FIQA 反而下降，却最接近原图。这说明：

> 对人眼更自然、对质量模型分数更高，不代表保留了更多真实身份信息。

因此，CR-FIQA 最终降为诊断信号，不再参与正式分桶和产品决策。

## 六、正式实验如何保证公平

在多轮试错后，我们冻结了统一实验协议。所谓“冻结”，就是在看最终结果前固定以下内容，所有方案不得单独调数据或阈值：

- 使用同一份 MEVID actor check-in Gallery；
- 使用同一份官方 Query 列表；
- 每条 Query 固定抽取 24 帧；
- 每条 Query 独立选择一张 face-best；
- 使用同一个 ArcFace 模型；
- 使用同一个 `score >= 0.45` 产品接受标准；
- 所有方案使用相同的 Query、Gallery 和身份映射；
- 每个超分后端单独缓存和留痕，避免串用结果。

最终 316 条官方 Query 被固定分为：

| 类型 | 数量 | 产品含义 |
| --- | ---: | --- |
| direct | 34 | 原图可直接进入识别 |
| recoverable | 40 | 有脸且存在修复空间，是超分主检验组 |
| unusable | 82 | 有脸，但信息不足或风险太高，应拒绝 |
| none | 160 | 没有可用人脸 |

共有 156 条 Query 可以检测并对齐人脸。

正式矩阵分成三类：

- **A 原图基线**：所有可对齐人脸都保留原图。
- **B 全量替换**：所有可对齐人脸分别交给 GFPGAN、CodeFormer 或 Real-ESRGAN。
- **C 产品路由**：direct 保留原图，recoverable 使用指定超分，unusable 和 none 拒绝。

B 组回答“如果无条件使用超分会怎样”；C 组回答“如果按产品规则只修可修复样本会怎样”。

## 七、正式结果

### 1. 主结果：40 条 recoverable Query

这是最适合判断超分价值的一组，因为它排除了 direct、unusable 和 none 的干扰。

- 原图：26/40（65.0%）。
- GFPGAN：8/40（20.0%），下降 45.0 个百分点，救回 0、损害 18。
- CodeFormer：11/40（27.5%），下降 37.5 个百分点，救回 0、损害 15。
- Real-ESRGAN：18/40（45.0%），下降 20.0 个百分点，救回 1、损害 9。
- 两个纯缩放控制：均为 26/40（65.0%）。

三种超分都没有超过原图。Real-ESRGAN 相对最好，速度最快、身份特征漂移也最小，但它仍比原图少认对 8 条。

### 2. 156 条可对齐 Query 的整体结果

整体数据上的趋势与 recoverable 主组一致：

| 方案 | 第一名身份正确 |
| --- | ---: |
| A 原图 | 80/156（51.3%） |
| B1 GFPGAN 全量替换 | 47/156（30.1%） |
| C1 GFPGAN 产品路由 | 37/156（23.7%） |
| B2 CodeFormer 全量替换 | 58/156（37.2%） |
| C2 CodeFormer 产品路由 | 40/156（25.6%） |
| B3 Real-ESRGAN 全量替换 | 74/156（47.4%） |
| C3 Real-ESRGAN 产品路由 | 47/156（30.1%） |

C 组包含主动拒绝 unusable 样本的产品逻辑，因此它的原始正确数量不能单独用来评价算法强弱。判断超分本身是否有帮助，仍以相同 recoverable 样本上的 A/B 对比为主。

Rank-5 结果也没有改变方案排序：原图为 60.3%，Real-ESRGAN 全量替换为 55.8%，其余方案更低。更重要的是，Rank-5 只代表正确身份进入前五名候选，不能替代 Top-1 加阈值的产品判定。

## 八、实验结果如何反向推动产品修改

这轮实验没有止于“模型分数对比”，还直接改变了产品实现。

### 1. 超分默认关闭

正式结果证明，当前超分更可能改变身份特征，而不是稳定恢复身份信息。因此：

- recoverable 人脸继续使用原始对齐脸；
- 超分后端可以插拔和显式选择，但默认关闭；
- 超分图不能自动进入 Gallery。

### 2. 默认人脸后端统一为 ArcFace

正式阈值和超分实验都基于 ArcFace。产品默认也改为 ArcFace，避免实验使用一套模型、线上默认使用另一套模型。AdaFace 仍可切换，但需要单独校准阈值。

### 3. Gallery 候选与入库证据拆开

过去“Rank-5”容易同时被理解为“看五个候选”和“用五帧建库”。现在两件事已经分开：

- Gallery 候选深度只用于比较第一名、第二名和内部歧义；
- 新身份入库可以要求 1、3 或 5 个时间分散的 Query 帧共同支持；
- 多帧证据只能阻止有歧义的入库，不能把低分候选提升成匹配成功。

### 4. 人脸和人形使用各自的最佳帧

人体最佳帧继续服务于人形 ReID，人脸最佳帧独立选择。这样避免“全身清楚但脸很差”的画面进入人脸识别和建库流程。

## 九、目前能确认什么，不能确认什么

### 可以确认

1. 在当前 MEVID、ArcFace 和冻结协议下，GFPGAN V1.3、CodeFormer `w=1`、Real-ESRGAN x2plus 都没有提高 recoverable 人脸的身份识别结果。
2. GFPGAN 和 CodeFormer 的人眼观感或 FIQA 提升，不能转化为身份识别提升。
3. Real-ESRGAN 的身份漂移最小、速度最快，是三种方案中风险最低的一个，但仍未超过原图。
4. 结果下降不是简单尺寸变化造成的。
5. FIQA 不适合直接作为当前产品的分桶、建库或路由条件。
6. 目前更值得投入的是原始采集、face-best 选帧、Gallery 质量和多帧一致性。

### 不能确认

1. 不能证明所有超分算法对所有人脸任务都无效。
2. 不能把 MEVID 的结果直接等同于客户真实摄像头环境。
3. recoverable 主组只有 40 条，Real-ESRGAN 的 1 条救回仍需要更多独立身份复验。
4. 不能用 Rank-5 较高来宣称产品已经识别成功。
5. 不能用“图片更清楚”或“FIQA 更高”替代身份正确性评估。

## 十、下一阶段建议

建议按以下优先级继续：

1. **补客户域数据**：收集真实摄像头中的清晰建库照、独立模糊 Query 和可靠身份标签。
2. **改善采集与选帧**：优先寻找更大、更正、更清晰的人脸，而不是先修复已经丢失的信息。
3. **使用多帧证据**：让多个时间分散的原始帧共同验证身份和入库资格，但不降低 Top-1 阈值。
4. **研究身份保持型增强**：如果继续做超分，应把身份 embedding 保持、救回/损害和误识风险作为主要目标，而不是只看视觉质量。
5. **扩大正式样本**：特别是扩充 recoverable 和跨摄像头独立身份，复验 Real-ESRGAN 是否存在稳定收益子集。
